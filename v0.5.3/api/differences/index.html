Differences from Base

AcceleratedKernels' functions with Base's names take the arguments Base's do, but follow contracts of their own, modelled on GPU libraries such as CUB: init is applied once, empty inputs have no implicit result, and results have one documented type. Base's rules that exist for Base's own reasons (empty results chosen per operator, typeof(init) as the result type along dims, and so on) are left to front-ends: GPUArrays.jl, for example, implements Base's API for GPU arrays on top of AcceleratedKernels and reproduces Base's results.
